این راهنما نحوه نصب و اجرای نودهای راه دور `xray-checker` را در شرایط شبکه پیچیده توضیح می‌دهد: فایروال‌های شرکتی، پروکسی‌های سازمانی، NAT، شبکه‌های ایزوله و فیلتر بودن دسترسی مستقیم به GitHub یا Docker Hub.

---

## ۱. معماری جریان‌های شبکه در نود

برای اطمینان از عملکرد صحیح تست پروکسی‌ها و ارسال گزارش‌ها به سرور اصلی، ترافیک شبکه به ۴ مسیر کاملاً مجزا تقسیم شده است:

```
                  ┌──────────────────────────────────────────────────────────┐
                  │                    نود بررسی (Node)                      │
                  └─────┬──────────────────┬───────────────────┬─────────────┘
                        │                  │                   │
             (1) گزارش مستقیم       (2) پینگ مستقیم    (3) تست تونل       (4) بوت‌استرپ (اختیاری)
             REPORT_URL             TCP/UDP            SOCKS5 127.0.0.1    BOOTSTRAP_PROXY
                        │                  │                   │                   │
                        ▼                  ▼                   ▼                   ▼
                  ┌───────────┐      ┌───────────┐       ┌───────────┐       ┌───────────┐
                  │ سرور اصلی │      │   سرور    │       │ Xray Core │       │  پروکسی   │
                  │  (Master) │      │  پروکسی   │       │  Inbound  │       │  سازمانی  │
                  │(direct/VPN│      │ (پورت ۴۴۳)│       │  (تونل)   │       │(10809/3128│
                  └───────────┘      └───────────┘       └─────┬─────┘       └─────┬─────┘
                                                               │                   │
                                                               ▼                   ▼
                                                         سایت‌های هدف         پایگاه‌های Geo و
                                                         (Cloudflare,        اشتراک‌ها
                                                          Google 204)        (GitHub و غیره)
```

1. **ارسال گزارش به سرور اصلی (`REPORT_URL`):**
   - گزارش مستقیماً به سرور اصلی ارسال می‌شود.
   - سیستم خودکار `NO_PROXY` آدرس سرور اصلی، `localhost` و رنج‌های خصوصی RFC1918 را از مسیر پروکسی سیستم معاف می‌کند.
2. **پینگ مستقیم پورت پروکسی (`TCP/UDP`):**
   - در دسترس بودن مستقیم پورت (مانند ۴۴۳) را از سرور نود بررسی می‌کند.
   - این بررسی مستقیماً از سوکت‌های بومی سیستم‌عامل (`net.Dialer`) انجام می‌شود و پروکسی‌های سیستم را نادیده می‌گیرد.
3. **بررسی نقاط پایانی هدف (Cloudflare، Google 204):**
   - این ترافیک **از داخل تونل رمزگذاری‌شده پروکسی** از طریق اینباند محلی SOCKS5 عبور می‌کند (`127.0.0.1:100xx`).
   - فایروال محلی نود قادر به مشاهده یا فیلتر کردن این ترافیک نیست. خطاهای تایم‌اوت به معنای وجود اختلال در مسیر، IPv6 یا فیلترینگ خود سرور پروکسی است.
4. **دانلود پایگاه‌داده‌های Geo و اشتراک‌ها (`BOOTSTRAP_PROXY`):**
   - اگر دسترسی مستقیم به GitHub برای دانلود GeoIP/GeoSite یا اشتراک‌ها مسدود باشد، می‌توانید `BOOTSTRAP_PROXY=http://proxy:port` را تنظیم کنید.
   - این پروکسی **فقط** برای دانلود فایل‌های ضروری استفاده می‌شود و تأثیری بر ارتباط با سرور اصلی یا بررسی پروکسی‌ها ندارد.

## ۲. روش اول: استقرار با داکر کامپوز (Docker Compose)

در ایمیج `ghcr.io/vlv-code/xray-checker-tg-bot:latest`، پایگاه‌داده‌های `geosite.dat` و `geoip.dat` از قبل قرار داده شده‌اند تا کانتینر بدون نیاز به دانلود اولیه از گیت‌هاب فوراً اجرا شود.

از قالب آماده [docker-compose.node.yml](https://github.com/vlv-code/xray-checker-tg-bot/blob/main/docker-compose.node.yml) استفاده کنید:

```yaml
services:
  xray-node:
    image: ghcr.io/vlv-code/xray-checker-tg-bot:latest
    container_name: xray-node
    restart: unless-stopped
    environment:
      # آدرس سرور اصلی و توکن اختصاصی نود (ایجاد شده با دستور /nodeadd <name> در ربات)
      - REPORT_URL=http://<YOUR_MASTER_IP>:2112/api/v1/nodes/report
      - REPORT_TOKEN=CHANGE_ME_TO_YOUR_NODE_BEARER_TOKEN
      # در صورت نیاز به پروکسی سازمانی برای دانلود:
      # - BOOTSTRAP_PROXY=http://192.168.27.121:10809
    volumes:
      - node-data:/app/data
      - node-geo:/app/geo

volumes:
  node-data:
  node-geo:
```

اجرا:
```bash
docker compose -f docker-compose.node.yml up -d
```

## ۳. روش دوم: استقرار از طریق Systemd (بدون داکر)

برای سرورهایی که داکر در دسترس نیست:

1. فایل اجرایی `xray-checker` را به مسیر `/usr/local/bin/xray-checker` کپی کرده و دسترسی اجرایی بدهید:
   ```bash
   chmod +x /usr/local/bin/xray-checker
   ```

2. کاربر سیستمی و پوشه‌های مورد نیاز را بسازید:
   ```bash
   useradd -r -s /bin/false xray-checker
   mkdir -p /opt/xray-checker/geo /opt/xray-checker/data
   chown -R xray-checker:xray-checker /opt/xray-checker
   ```

3. فایل سرویس systemd را کپی کنید:
   ```bash
   cp scripts/xray-checker-node.service /etc/systemd/system/xray-checker-node.service
   ```

4. مقادیر `REPORT_URL` و `REPORT_TOKEN` را در `/etc/systemd/system/xray-checker-node.service` تنظیم کنید.

5. سرویس را فعال و اجرا کنید:
   ```bash
   systemctl daemon-reload
   systemctl enable --now xray-checker-node
   ```

## ۴. تفسیر وضعیت‌ها در ربات تلگرام

### پورت مستقیم پاسخ نمی‌دهد (`⚠️`) ولی تونل فعال است:
- **نمایش:** `• TCP (443): ⚠️ Timeout (فیلتر پرووایدر یا محافظت ضد اسکن سرور، اما تونل فعال است)`
- **دلیل:** پروتکل‌های مدرن دور زدن فیلترینگ (Reality، Trojan، ShadowTLS) بسته‌های TCP SYN ناشناس را نادیده می‌گیرند ("stealth mode").
- **معیار اصلی:** اگر تست HTTP 204 از داخل تونل موفق باشد، پروکسی کاملاً سالم و آماده استفاده است.

### خطای یک مقصد درون تونل (مثلاً تایم‌اوت گوگل در حالی که کلودفلر کار می‌کند):
- **نمایش:** `• gstatic: ❌ Timeout (تایم‌اوت پاسخ از طریق پروکسی: مشکل مسیر/IPv6 روی سرور پروکسی یا اختلال سرویس)`
- **دلیل:** ترافیک گوگل از درون تونل رمزگذاری‌شده سرور پروکسی عبور می‌کند و ارتباطی به شبکه محلی نود ندارد. این مشکل نشان‌دهنده عدم اتصال IPv6 روی سرور پروکسی یا لیمیت شدن موقت IP سرور توسط گوگل است.\n
