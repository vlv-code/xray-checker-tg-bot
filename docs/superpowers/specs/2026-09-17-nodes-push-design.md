# Механика нод: удалённые инстансы чекера с push-отчётами

Дата: 2026-09-17
Статус: утверждённый дизайн (brainstorming), ждёт ревью
Ветка: `feat/nodes-push`

## 1. Проблема и цель

Сейчас инстанс xray-checker-tg-bot автономен: он сам чекает свои подписки и сам
слёт алерты в Telegram. Нужна механика «нод»: кроме локальных проверок мастер
получает результаты проверок с удалённых инстансов чекера (тот же образ, но
без токена бота — headless) и:

- алертит по прокси каждой ноды — пер-(нода, прокси), без агрегации;
- следит за здоровьем самих нод (нода молчит — алерт);
- показывает ASN провайдера ноды-чекера в алертах и сводках;
- позволяет из TG-бота мастера управлять подписками нод.

Пересечение подписок между нодами (и с мастером) допустимо: каждая пара
(нода, прокси) — независимая наблюдаемая сущность.

## 2. Роли и топология

- **Мастер** — образ с `TELEGRAM_BOT_TOKEN`. Локальные проверки + ingest-эндпоинт
  для отчётов + весь алерт-пайплайн + TG-команды.
- **Нода** — тот же образ без `TELEGRAM_BOT_TOKEN` (бот не запускается). Локальный
  чек-цикл как обычно; после каждого цикла POST-ит снапшот результатов мастеру;
  в ответ получает желаемый список управляемых подписок и применяет разницу.

Транспорт — **push (нода → мастер)**. Ноды не открывают никаких входящих
портов и работают из-за NAT. Голые апстрим-инстансы xray-checker без нашего
образа в топологию не встраиваются (pull-опрос — возможная фаза 2, вне скоупа).

## 3. Конфигурация

Формат — как всё в `config/config.go` (kong, env-переменные, валидация при старте).

### Мастер

| Переменная | Default | Описание |
|---|---|---|
| `NODES` | — | Список нод `имя\|токен`, через запятую в env или повторяемым флагом `--node`. Имена уникальны и непусты, токены непустые. Пусто — фича выключена, поведение идентично текущему. |
| `NODES_STORE_PATH` | `node_subs.json` | Файл desired-состояния подписок нод (см. §7). |

Ingest-эндпоинт монтируется на существующий HTTP-порт (2112 по умолчанию)
тогда и только тогда, когда `NODES` непуст.

### Нода

| Переменная | Default | Описание |
|---|---|---|
| `REPORT_URL` | — | URL ingest-эндпоинта мастера, например `https://master.example:2112/api/v1/nodes/report`. Непусто — репортинг включён. |
| `REPORT_TOKEN` | — | Токен, совпадающий с записью ноды в `NODES` мастера. |

Валидация: `REPORT_URL` без `REPORT_TOKEN` — ошибка старта (и наоборот).
`REPORT_URL` + `TELEGRAM_BOT_TOKEN` на одном инстансе не запрещено, но не
рекомендуется (роль определяется явно).

## 4. Протокол отчётов

### Запрос

```
POST /api/v1/nodes/report
Authorization: Bearer <REPORT_TOKEN>
Content-Type: application/json
```

```json
{
  "version": "1.2.3",
  "checkIntervalSec": 300,
  "checkMethod": "ip",
  "hostIP": "203.0.113.7",
  "proxies": [
    {
      "stableId": "a1b2c3",
      "name": "de-01",
      "subName": "sub1",
      "groupName": "g1",
      "protocol": "vless",
      "address": "host.example:443",
      "online": true,
      "disabled": false,
      "latencyMs": 123,
      "lastCheck": 1758100000,
      "lastErrorCategory": 0,
      "lastErrorMsg": ""
    }
  ]
}
```

- `hostIP` — внешний IP ноды (нода уже знает его: `ProxyChecker.GetCurrentIP`,
  кэш с TTL 1ч). Нужен мастеру для ASN.
- Тело ограничено 5 MiB. Всё, что не проходит схему — 400, отчёт игнорируется.

### Ответ

```json
{ "managedSubs": ["https://sub1.example/link", "https://sub2.example/link"] }
```

Полный желаемый список подписок, управляемых мастером, для этой ноды.
Нода сверяет его со своим локальным набором управляемых подписок (§6).

### Семантика доставки

At-least-once силами следующего цикла: потерянный POST не ретраится —
следующий чек-цикл (~`PROXY_CHECK_INTERVAL` ноды) пришлёт свежий снапшот и
получит актуальный `managedSubs`.

## 5. Компоненты мастера

### 5.1. Пакет `nodes`

- `Registry` — состояние нод под `sync.RWMutex`:
  - `token → имя` (identity по токену, не по самодекларации);
  - на ноду: `lastReport time.Time`, `lastSnapshot []metrics.ProxyMetric`,
    `checkInterval`, `version`, `hostIP`, состояние `pending | up | down`,
    закэшированный ASN.
- `HandleReport` — HTTP-хендлер: Bearer-аутентификация (сравнение токенов
  constant-time, неизвестный токен — 401 без деталей), декодирование,
  валидация, запись снапшота, ответ с `managedSubs`.
- Маппинг отчёта → `[]metrics.ProxyMetric`:
  - `StableID = "<имяНоды>/<stableId>"` — неймспейс, исключающий коллизии
    с локальными прокси и между нодами при пересечении подписок;
  - новые поля `NodeName`, `NodeASN` (у локальных прокси — пустые, обратная
    совместимость);
  - имя прокси не искажается — нода отображается отдельной строкой.
- `MergedSnapshot(local []metrics.ProxyMetric) []metrics.ProxyMetric` —
  локальный снапшот + снапшоты всех нод в состоянии `up`.
- `Sweeper` — gocron каждые 30 сек: если `now > lastReport + 2×checkInterval + 60s`
  и нода `up` — переводит в `down`; если отчётов ещё не было (`pending`) —
  молча (никаких алертов до первого успешного отчёта). Возврат в `up` —
  первым же принятым отчётом.

### 5.2. Интеграция в `main.go` и пайплайн алертов

Ключевое ограничение: `Bot.ProcessSnapshot` стирает состояние ID, которых нет
в переданном снапшоте (`telegram/alerts.go:155`). Поэтому в бота всегда уходит
**один объединённый** снапшот — локальные + все живые ноды.

Три источника событий зовут один и тот же колбэк
`onSnapshotUpdate()` → `tgBot.ProcessSnapshot(registry.MergedSnapshot(proxyChecker.MetricsSnapshot()))`:

1. конец локального чек-цикла (`runCheckIteration`);
2. принятый отчёт ноды (`HandleReport`);
3. переход ноды по здоровью (Sweeper или первый отчёт).

Grace-очистка при дауне ноды: при переходе `up → down` merged-снапшот **один
раз** включает прокси ноды с `Disabled=true` — существующая ветка
`ProcessSnapshot` сама удалит их активные алерты и состояние. Дальше нода из
снапшота исчезает. При возврате её прокси приходят как новые ID —
seeding-семантика не даёт ложных алертов.

Алертами нод управляет отдельный метод `Bot.ProcessNodesHealth(states []NodeHealth)`:
переход `up → down` — «🔴 Нода node-1 (AS9009 M247) недоступна», `down → up` —
«✅ Нода node-1 вернулась». Инфраструктурные алерты ходят без тихих часов.

Без `NODES` ни Registry, ни ingest, ни Sweeper не создаются — текущее
поведение не меняется.

## 6. Репортер на ноде

После каждого завершённого чек-цикла (включая `--run-once`):

1. Собрать отчёт из `proxyChecker.MetricsSnapshot()` (поле `hostIP` — из
   `GetCurrentIP()`).
2. POST на `REPORT_URL`. Ошибка сети — `Warn` в лог, состояние подписок не
   трогаем, следующий цикл всё выровняет.
3. Успех → сверка `managedSubs` с локальными управляемыми подписками:
   - нет локально, есть в desired — провалидировать (`ReadFromSource`, как в
     `/addsub`: пустая/битая подписка не добавляется, `Warn` в лог) → добавить
     в `URLStore` с пометкой «managed»;
   - есть локально с пометкой «managed», нет в desired — удалить;
   - что-то изменилось — `reloadSubscriptions()` (то же замыкание и `reloadMu`,
     что у периодического апдейтера и `/addsub`).
4. Пометка «managed» нужна, чтобы reconciliation не трогала статические
   (`SUBSCRIPTION_URL` env) и добавленные локальным ботом подписки (инстанс
   может совмещать роли). В `URLStore` появляется поле владельца записи.

## 7. Управление подписками нод с мастера

- Desired-состояние: `NODES_STORE_PATH` (`node_subs.json`), карта
  `имяНоды → [url]`, персистентно, загружается при старте.
- `telegram.NodeManager` (интерфейс в пакете `telegram`, реализация в `main`,
  по образцу `SubscriptionManager`):
  - `List() []NodeHealth` — для `/nodes`;
  - `ManagedSubs(node string) ([]ManagedSub, error)` — desired-список + счётчик
    прокси по подписке из последнего отчёта (в отчёте есть `subName` у прокси);
  - `AddSub(node, url) error` / `RemoveSub(node, url) error` — правка desired-состояния.
- Применение — при следующем отчёте ноды (задержка ≤ её `checkInterval`).
  Команды отвечают сразу: «поставлено, нода применит при следующем отчёте».

### Команды TG

| Команда | Действие |
|---|---|
| `/nodes` | Сводка: 🟢/🔴, ASN, версия, прокси X/Y онлайн, age последнего отчёта, интервал чеков. |
| `/nodesubs <имя>` | Desired-подписки ноды + счётчики прокси из последнего отчёта. |
| `/nodeaddsub <имя> <url>` | Добавить в desired. |
| `/nodedelsub <имя> <url>` | Убрать из desired. |

Все команды — только для allowed-чатов (существующий механизм). Существующий
`/togglenode` (отключение прокси-хоста от проверок) не меняется; в `/help`
уточняются формулировки, чтобы не путать «ноду-инстанс» и «хост-ноду прокси».

## 8. ASN нод

- База: ASN-mmdb (db-ip asn-lite, `.mmdb.gz`, свободная лицензия CC-BY 4.0).
  URL — env `ASN_DB_URL` с зашитым на момент релиза дефолтом (в URL есть месяц).
  Скачивание — по схеме `xray/geo_files.go`: атомарно (tmp + rename), с
  graceful-деградацией «нет файла/сети — фича выключена, `Warn` в лог».
  Даунлоадер умеет gzip (`compress/gzip`).
- Чтение: `github.com/oschwald/maxminddb-golang` (pure Go, без cgo).
- Lookup: `hostIP` из отчёта → номер ASN + организация; кэш на ноду в Registry.
  Частный IP / нет базы / ошибка — пустой ASN, на алертинг не влияет.
- Отображение: `/nodes`, алерты нод, строка в алертах прокси нод
  («📍 via node-1 · AS9009»).

## 9. Веб и метрики мастера (фаза 1 — минимум)

- `/metrics` и веб-панель не меняются: показывают локальные прокси, как сейчас.
- Добавляется `GET /api/v1/nodes` — JSON-сводка (имя, up, ASN, версия, hostIP,
  online/total, lastReport, checkInterval), защищённая так же, как остальные
  `/api/v1/*` маршруты мастера.
- Лейбл ноды в метриках и секция нод на панели — фаза 2, вне этой спеки.

## 10. Безопасность

- Identity ноды — только по Bearer-токену; сравнение constant-time; неизвестный
  токен — 401 без указания, близок ли токен.
- Ingest НЕ прячется за basic-auth метрик — у него своя аутентификация, иначе
  нодам пришлось бы знать креды метрик мастера.
- Лимит тела 5 MiB; некорректный JSON — 400.
- Публичный интернет мастер↔нода: рекомендован HTTPS (reverse proxy);
  задокументировать. Сам endpoint — это только приём статусов, никаких команд
  «на исполнение» вниз не уходит (только declarative desired-список подписок).
- ASN-база скачивается с фиксированного URL; подмена через env `ASN_DB_URL` —
  зона ответственности оператора.

## 11. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Неизвестный/кривой токен | 401, счётчик нод не трогаем. |
| Битый JSON / превышен лимит | 400, игнор. |
| Нода молчит дольше дедлайна | `down`: алерт + grace-очистка её прокси-алертов. |
| Первый отчёт ноды / после дауна | Прокси приходят как новые — без ложных алертов (seeding). |
| Нода прислала 0 прокси | Легитимно (нет подписок), не ошибка. |
| Валидация добавляемой подписки на ноде провалилась | Не добавляется, `Warn`; desired на мастере остаётся — расхождение видно в `/nodesubs` (нет счётчика прокси у URL). |
| POST отчёта упал | `Warn`, подписки не трогаем, следующий цикл повторит. |
| ASN недоступен | Пустое значение везде, деградация без алертов. |
| Мастер без `NODES` / нода без `REPORT_URL` | Фича полностью выключена, поведение как сегодня. |

## 12. Тестирование

- `nodes` (мастер): аутентификация ingest (401/200), валидация тела и лимит,
  маппинг+неймспейсинг, коллизия одинаковых stableId от двух нод, Sweeper
  (`pending` без алертов, `up→down` c grace-снапшотом `Disabled=true`,
  `down→up`), `MergedSnapshot` под конкурирующими вызовами.
- Репортер (нода): сборка отчёта из снапшота, reconciliation
  (добавить/убрать/no-op, изоляция managed от static/bot-added, битая подписка
  не добавляется), упавший POST не меняет подписки.
- `node_subs.json`: персистентность, загрузка при старте.
- `telegram`: форматтеры с `NodeName`/`NodeASN`, `ProcessNodesHealth`
  (переходы, повторы), команды `/node*` с мок-`NodeManager`.
- `GET /api/v1/nodes`: auth и содержимое.
- Интеграционно: httptest-мастер + фейк-нода — даун прокси ноды → алерт;
  даун ноды → алерт + чистка; возврат ноды → без ложных алертов.
- Регресс: весь существующий набор зелёный при пустых `NODES`/`REPORT_URL`.

## 13. Вне скоупа (фазы 2+)

- Pull-опрос голых апстрим-инстансов без нашего образа.
- Лейбл ноды в `/metrics` и секция нод на веб-панели.
- Агрегация по кворуму для пересекающихся подписок.
- Двусторонние команды нодам (reload now, смена интервала) — только
  declarative подписки.
